# План реализации: Устранение оверинжиниринга, повышение стабильности и качества (#111)

## 1. Контекст и цели
В ходе архитектурного и кодового аудита плагина `@goodandready/dsh-model-sync` (Issue #111) выявлены:
1. **Гонки параллельной записи (`saveConfig`)**: если несколько вызовов `saveConfig` происходят параллельно (или в момент обновления настроек), мутации настроек могут перезаписывать друг друга.
2. **Безопасность HTTP API (`trusted(req)`)**: `lib/http.js` пропускает запросы без заголовка `Origin` как доверенные (`if (!origin) return true`). Для браузерных мутаций это создает риск CSRF.
3. **Безопасность regex политик (`lib/policy.js`)**: regex компилируются без проверки на catastrophic backtracking и без обработки некорректных шаблонов при фильтрации.
4. **Упрощение планировщика (`lib/scheduler.js`)**: убрать оверинжиниринг per-provider джиттера/TTL в таймерах, сделать чистый и предсказуемый интервал; добавить мгновенный первый запуск при включении расписания, если синхронизация еще не проводилась.
5. **Оптимизация размера истории и каталогов в YAML**: убрать сохранение избыточных дубликатов каталогов в истории `history`, сохранять только diff и метаданные, снижая нагрузку на парсер DSH `settings.yaml`.

## 2. Архитектура изменений

### Блок 1. Атомарность сохранения настроек (`lib/index.js`)
- Внедрить последовательную очередь (async mutex / promise chain) для `saveConfigImpl`.
- Все параллельные вызовы `saveConfig(patch)` выстраиваются в очередь, получая свежий снимок и последовательно применяя мутации к `settingsScope`.

### Блок 2. Безопасность HTTP API (`lib/http.js`)
- В `trusted(req)`:
  - Проверять заголовок `sec-fetch-site`: отклонять `cross-site`.
  - Для мутирующих методов (`POST`, `PUT`, `DELETE`, `PATCH`):
    - Если `sec-fetch-site` равен `same-origin` или `same-site`, разрешать.
    - Если передан `origin`, он обязан совпадать с `host`.
    - Если `origin` отсутствует, проверять `referer` (если он есть, хост должен совпадать). Если и `origin`, и `referer` отсутствуют, но присутствует браузерный `sec-fetch-mode`, блокировать. Локальные API-клиенты (например, без браузерных заголовков) разрешать только при совпадении Host/loopback.

### Блок 3. Безопасная валидация regex в политиках (`lib/policy.js`)
- Защитить `compilePatterns` и `filterModels`: корректная обработка `SyntaxError`, экранирование опасных шаблонов, ограничение длины строки поиска.

### Блок 4. Предсказуемый планировщик и первый запуск (`lib/scheduler.js`)
- При старте планировщика (`start()`):
  - Если расписание включено и `lastRunAt === null` (синхронизация никогда не запускалась), немедленно запускать первый `tick()`, а затем продолжать по таймеру интервала.
- Упростить вычисление задержек без переусложнения джиттерами.

### Блок 5. Оптимизация истории (`lib/history.js`)
- В `createHistoryEntry`: для снижения веса `settings.yaml` хранить в `before` и `after` только компактные метаданные моделей (`id`, `name`), необходимые для отката и диффа, без раздувания vendor-специфичными полями.
